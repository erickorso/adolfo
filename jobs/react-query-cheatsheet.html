TanStack React Query — Guía rápida

Server state · cache · sync · v5 · Entrevistas front React

¿Qué es y cuándo usarlo?

React Query gestiona server state: datos que viven en el API, no en React. Cache, refetch, loading/error, deduplicación y sincronización entre componentes.

Usar QueryNO usar Query (usar useState/Context)
GET listados, detalle, búsquedasTema UI, modal abierto, step wizard
POST/PUT/DELETE al servidorFormulario antes de submit
Datos compartidos entre pantallasAuth token en Context (ok)

Setup mínimo

npm i @tanstack/react-query

// app/providers.tsx
'use client'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { useState } from 'react'

export function Providers({ children }) {
  const [client] = useState(() => new QueryClient({
    defaultOptions: {
      queries: {
        staleTime: 60_000,      // 1 min fresh
        retry: 1,
        refetchOnWindowFocus: false,
      },
    },
  }))
  return (
    <QueryClientProvider client={client}>
      {children}
    </QueryClientProvider>
  )
}

useQuery — leer datos

function PolicyDetail({ id }: { id: string }) {
  const { data, isLoading, isError, error, isFetching, refetch } = useQuery({
    queryKey: ['policy', id],
    queryFn: () => fetch(`/api/policies/${id}`).then(r => {
      if (!r.ok) throw new Error('Failed')
      return r.json()
    }),
    staleTime: 5 * 60_000,
    enabled: !!id,
  })

  if (isLoading) return <p>Loading…</p>
  if (isError) return <p>Error: {error.message}</p>
  return (
    <div>
      {isFetching && <span>Updating…</span>}
      <h1>{data.name}</h1>
      <button onClick={() => refetch()}>Refresh</button>
    </div>
  )
}

useMutation — escribir

const queryClient = useQueryClient()

const mutation = useMutation({
  mutationFn: (body: PolicyInput) =>
    fetch('/api/policies', {
      method: 'POST',
      body: JSON.stringify(body),
    }).then(r => r.json()),
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ['policies'] })

  onError: (err) => toast.error(err.message),

// Uso

Patrones avanzados

Optimistic update

useMutation({
  mutationFn: updatePolicy,
  onMutate: async (newData) => {
    await queryClient.cancelQueries({ queryKey: ['policy', id] })
    const previous = queryClient.getQueryData(['policy', id])
    queryClient.setQueryData(['policy', id], newData)
    return { previous }
  },
  onError: (_err, _vars, ctx) => {
    queryClient.setQueryData(['policy', id], ctx?.previous)
  },
  onSettled: () => {
    queryClient.invalidateQueries({ queryKey: ['policy', id] })
  },
})

Custom hook (patrón)

function usePolicy(id: string) {
  return useQuery({
    queryKey: ['policy', id],
    queryFn: () => api.getPolicy(id),
    enabled: !!id,
  })
}

function useUpdatePolicy() {
  const qc = useQueryClient()
  return useMutation({
    mutationFn: api.updatePolicy,
    onSuccess: (_, { id }) => {
      qc.invalidateQueries({ queryKey: ['policy', id] })
    },
  })
}

Side effects — cómo los maneja Query

Query no reemplaza useEffect para todo. Server state → Query/Mutation. UI/DOM → useEffect.

TipoHerramienta
Fetch + cache + syncuseQuery / useMutation
Efectos tras POST/PUT/DELETEcallbacks de useMutation
Título, analytics, focususeEffect (si no es del API)
Errores globales de queriesQueryCache onError

useMutation — ciclo de vida (patrón principal)

useMutation({
  mutationFn: updatePolicy,
  onMutate: async (vars) => {
    // ANTES: optimistic update, cancelQueries
    await queryClient.cancelQueries({ queryKey: ['policy', id] })
    const previous = queryClient.getQueryData(['policy', id])
    queryClient.setQueryData(['policy', id], vars)
    return { previous }
  },
  onSuccess: (data, vars) => {
    // toast, redirect, invalidate, analytics
    queryClient.invalidateQueries({ queryKey: ['policies'] })
  },
  onError: (err, vars, ctx) => {
    // rollback optimistic
    queryClient.setQueryData(['policy', id], ctx?.previous)
    toast.error(err.message)
  },
  onSettled: () => {
    // SIEMPRE al final (ok o error)
  },
})

useQuery — evitar onSuccess (v5)

Mejor derivar en render. Si hace falta efecto en DOM:

const { data, isSuccess } = useQuery({ ... })

useEffect(() => {
  if (isSuccess && data) document.title = data.name
}, [isSuccess, data])

Global — QueryCache / MutationCache

new QueryClient({
  queryCache: new QueryCache({
    onError: (error, query) => log(query.queryKey, error),
  }),
  mutationCache: new MutationCache({
    onSuccess: () => toast.success('Saved'),
  }),
})

enabled — evitar fetch prematuro (sin useEffect)

useQuery({
  queryKey: ['policy', id],
  queryFn: () => fetchPolicy(id),
  enabled: !!id,  // no fetch hasta que id exista
})

❌ Anti-patterns

// ❌ fetch en useEffect
useEffect(() => { fetch('/api').then(setData) }, [])

// ✅ useQuery

// ❌ invalidate en useEffect tras flag manual
useEffect(() => { if (saved) invalidate(...) }, [saved])

// ✅ onSuccess en useMutation

Entrevista (EN): “Side effects tied to server ops go in mutation lifecycle hooks; global handlers on QueryCache. I don’t useEffect-fetch — I use enabled and queryKey instead.”

Entrevista — frases clave

  • “Server state is async, shared, and can go stale — Query owns that.”
  • “staleTime vs gcTime: fresh window vs garbage collection.”
  • “Invalidation over manual cache sync after mutations.”
  • “Optimistic UI with onMutate + rollback onError.”
  • “Side effects on mutations: onMutate → onSuccess/onError → onSettled.”
  • “queryKey hierarchy enables granular invalidation.”
